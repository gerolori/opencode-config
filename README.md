# opencode-config

Canonical OpenCode configuration for this user. It is a source checkout at
`~/.config/opencode` (on Windows, `C:\Users\hermes\.config\opencode`) and is also
the global config directory that OpenCode loads.

The design goal is a small always-loaded index, lazy and ignored memory, one level of
delegation, and exactly one external-retrieval worker. Everything else is a detail
document under `docs/`.

## Runtime snapshot

Verified on this host at the time of writing:

| Item | Value |
| --- | --- |
| OpenCode runtime | 1.19.5 |
| `@opencode-ai/plugin` (SDK) | 1.19.5 |
| Bun | 1.3.9 |
| Node | 25.6.1 |
| `autoupdate` | `false` |

OpenCode auto-updated independently from 1.18.18 to 1.19.5. Automatic updates are now
disabled in `opencode.jsonc`; upgrades are deliberate and manual. `package.json` and
`bun.lock` are intended source and should be committed together. `package-lock.json`
is ignored and may be regenerated by the runtime plugin installer; `bun.lock` remains
authoritative.

## Layout

```text
~/.config/opencode/
  AGENTS.md                 small always-loaded index
  README.md                 this file
  opencode.jsonc            base config (models, agents, permissions, MCP, plugins)
  opencode.host.example.jsonc   portable host override example
  opencode.private.local.json   this host's local override (ignored)
  package.json / bun.lock   SDK pin and authoritative lockfile
  agents/                   build, plan, code, review, explore, fetch, track, composio
  commands/                 slash-command templates
  instructions/             always-included instruction files
  plugins/                  auto-discovered local plugins (sqz, retrieval-policy)
  lib/                      plugin implementation shared by tests
  scripts/preflight.ts      environment/config probe
  tests/                    bun tests and typecheck fixtures
  docs/                     detailed docs and templates
  memory/                   ignored global memory (never committed)
```

OpenCode auto-discovers `plugins/*.ts`; do not also list those files in the `plugin`
array. `opencode.jsonc` lists only external plugins. `plugins/sqz.ts` and
`plugins/retrieval-policy.ts` load by discovery.

The nested `~/.config/opencode/.opencode/` directory is legacy project-shaped state,
not the config root. Its dead telemetry command/plugin/tokenizer assets were removed;
only its ignored `node_modules`, stale `package.json` / `package-lock.json`, and
`.gitignore` remain. Do not
reintroduce plugin code there.

## Agents and delegation

Exactly one delegation level:

```text
build / plan  ->  code | review | explore | fetch | track | composio
```

- `code` — scoped edits and narrow verification.
- `review` — read-only correctness, regression, scope, verification check.
- `explore` — read-only local discovery, including local Semble.
- `fetch` — the only worker allowed to touch external sources.
- `track` — Beads `br` / `bv` only.
- `composio` — one external-app workflow end-to-end.

There is no `research` agent; it was removed. Workers cannot spawn children. The
retrieval plugin denies `task` from child sessions and denies it entirely to agents
other than `build` / `plan`.

## Commands

Repository-level scripts (run from this directory):

```text

bun run preflight -- --config
```

Native OpenCode commands relevant here:

```text
opencode models [provider]     list the available catalog
opencode stats                 native token/cost statistics
opencode providers             manage provider credentials (alias: auth)
opencode debug config          show the resolved config
```

Slash commands in `commands/`:

| Command | Purpose |
| --- | --- |
| `/claim` | claim a bead through `track` |
| `/triage` | dependency-aware Beads triage through `track` |
| `/review-diff` | review the current diff with `review` |
| `/worktree` | start a task in a dedicated worktree |
| `/tokenscope` | point at native `opencode stats`; no in-session token tool exists |

### Token telemetry

There is no native in-session `tokenscope` or `context_usage` tool. The old
cwd-scoped plugin and tokenizer assets were dead and were removed. Use the native CLI:

```text
opencode stats [--days N] [--tools N] [--models [N]] [--project ""]
```

`/tokenscope` now states that plainly instead of calling a nonexistent tool. Do not
install heavy tokenizer dependencies to resurrect the old command.

## Tool contracts

### `retrieval_control`

Custom tool registered by `plugins/retrieval-policy.ts`.

```text
retrieval_control({ action: "status" | "extend", session_id?: string })
```

- `status` reports the caller's own budget by default. A `build` / `plan` parent may
  target a direct child session.
- `extend` is `build` / `plan` only, must name a direct child session, and grants
  +3 searches and +3 reads once. The plugin enforces caller identity and parentage.
- The tool never calls an MCP server.

### `tinyfish_search`

Custom tool registered by `plugins/retrieval-policy.ts`.

```text
tinyfish_search({ query: string, max_results?: 1..5 })
```

- Direct `GET https://api.search.tinyfish.ai` with the `X-API-Key` header.
- Returns URL/title/snippet evidence only; `evidence_type=snippet`.
- Never invokes TinyFish Agent, Browser, MCP, or wallet APIs.
- Only the `fetch` agent may call it.

### Retrieval behavior

- Per child session: 3 searches and 3 page reads.
- One parent-approved extension (+3/+3), then resume.
- At most 2 distinct providers per normalized query.
- Search preference: DuckDuckGo first, TinyFish next, then one healthy alternative.
- Semantic preference: Exa first, then one healthy alternative.
- Reads: built-in `webfetch`, then DuckDuckGo, then Exa.
- Unknown native `websearch` / `websearch_cited` are denied: the backend is unknown,
  possibly paid and unbounded.
- Failed auth, quota, CAPTCHA and access-denial walls are reported, never bypassed.
- Counts are local attempts, not vendor billing.

Full details: `docs/retrieval.md`.

## Native `opencode stats` vs plugin telemetry

`opencode stats` is the native, verified way to see usage and cost. The retrieval
plugin also records metadata-only local attempt counts in
`~/.local/share/opencode/retrieval/` (or `$XDG_STATE_HOME/opencode/retrieval`).
Those counts are operational state outside Git. They are not a general memory
detector and they are not vendor invoices.

## Providers and credentials

### Interactive ChatGPT orchestration

The intended strong-orchestrator flow in the TUI is:

```text
/connect -> OpenAI -> ChatGPT Plus/Pro -> browser
```

Then use `/models` to list the exact catalog available through the native OpenAI
provider. Do not guess model IDs. Test entitlement on one user model first, then pick
the main orchestrator model.

Constraints:

- Explicit worker agents remain on OpenRouter. Do not silently move them.
- A catalog entry is not proof of entitlement; only a real call proves it.
- A manual API-key fallback exists, but do not keep duplicate credentials and do not
  promise automatic failover.
- Until a successful ChatGPT authentication, the API path remains the default.
- Never copy `auth.json` between hosts.
- Do not claim a subscription or a paid key was verified unless it actually was.

### Worker pins and cost

Worker entries are pinned in config to specific model IDs/weights with low reasoning
options. The actual upstream provider routing and cost are not validated until a real
call is made. Do not present configured names as measured provider or billing facts.

### Exa

- The base `exa` MCP entry is disabled, with `oauth: false` and an `x-api-key` header
  from `{env:EXA_API_KEY}`.
- `plugins/retrieval-policy.ts` enables it only when `EXA_API_KEY` is present.
- A free account can be created at `https://dashboard.exa.ai/api-keys`.
- Exa's free plan is described as a recurring credit with no card and no automatic
  recharge. Do not state this as a guarantee if the user brings a paid key; paid-key
  billing is governed by that account.

### TinyFish

TinyFish is **not** a native MCP server in OpenCode 1.19.5. The custom
`tinyfish_search` tool is the only integration.

- Key: `TINYFISH_API_KEY` from `https://agent.tinyfish.ai/api-keys`.
- Adapter: direct `GET https://api.search.tinyfish.ai`.
- Free plan caps enforced by the plugin: 30/minute, 500/hour, 12,000/day.
- Snippets only. No TinyFish Agent, Browser, or wallet calls.

### Key entry

Do not paste keys into command lines or tracked files. Use a masked prompt so the
value is not left in shell history:

PowerShell:

```powershell
$secure = Read-Host -AsSecureString "TINYFISH_API_KEY"
$env:TINYFISH_API_KEY = [Runtime.InteropServices.Marshal]::PtrToStringBSTR(
  [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secure))
```

Bash:

```bash
read -rs TINYFISH_API_KEY && export TINYFISH_API_KEY
```

Restart OpenCode from the same process so the plugin and MCP clients inherit the
variable. Do not create tracked `.env` files, and do not dump authentication stores.

Missing keys must not block offline implementation. Report the exact manual command.

## Memory

Global memory is ignored and lives in `memory/`. It is read lazily through
`AGENTS.md` pointers, never by globbing the directory. The protocol — stable
instructions vs expiring state vs evidence cache, entry schema, freshness rules, and
the approval loop — is in `docs/memory.md`.

Only templates and protocol docs are tracked. Personal entries are never committed.
Project memory lives in `<project>/.opencode/memory/`; templates for it are under
`docs/templates/`.

## Setup

1. Keep the checkout at `~/.config/opencode`; never clone over an existing directory.
2. Install dependencies with `bun install`. The SDK pin and `bun.lock` are
   authoritative.
3. Use `opencode.host.example.jsonc` as the portable host overlay. It forwards
   `SEMBLE_MCP_DIR` and `EBAY_MCP_DIR` and contains no credentials.
4. Load a host overlay explicitly, for example with `OPENCODE_CONFIG`. The ignored
   `opencode.private.local.json` holds this host's Semble path but is not loaded
   automatically as of this writing.
5. Enter keys with the masked flows above, then restart from the same process.
6. Check `bun run preflight -- --config` and `bun run typecheck`.

Full details: `docs/setup.md`, `docs/providers.md`, `docs/portability.md`.

## Verification

```text
bun run typecheck
bun test
bun run preflight -- --config
opencode debug config
```

`preflight --config` parses the resolved config without printing secrets. It verifies
runtime presence, the SDK pin, installed SDK version, and lockfile policy, and reports
only key presence for the config.

## Honest constraints

- This repository documents intent and verified local facts; it does not prove an
  upstream provider, plan, entitlement, price, or wire cost.
- Retrieval budgets and circuit breakers are local policy. They reduce accidental
  spend; they are not a vendor-side quota guarantee.
- Exa/TinyFish free-tier terms and quotas can change. Re-check the vendor dashboard
  before relying on them.
- The nested `.opencode/` state, `opencode.private.local.json`, and host environment
  are cross-file dependencies that must be checked on each host.
- `sqz` currently resolves as `sqz-mcp.exe` and must be on `PATH`. That is a
  Windows-specific selection the integration owner still needs to generalize.
- The command `/tokenscope` describes a CLI action; an interactive agent may not have
  shell permission to run it.
- Aggregate metrics (for example a reported 85.1%) are aggregate, not per-task
  guarantees. Compare real, normal tasks instead of running a benchmark campaign:
  runtime, cache hits, reasoning, cost, retries, and success.
- No paid search/service accounts, OAuth sessions, or credentials are included here.
